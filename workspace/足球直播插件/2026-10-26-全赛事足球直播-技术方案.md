# 全赛事足球直播改造技术方案

> 从「FIFA World Cup 2026 单赛事插件」演进为「覆盖全部足球赛事的直播插件」：
> 五大联赛、欧冠、中超、世界杯/欧洲杯等国家队赛事统一支持，保持零配置（公共数据源、无 token）。

---

## 1. 背景与目标

### 1.1 背景

当前插件围绕 2026 美加墨世界杯开发，赛程/直播/积分榜/球队榜均以世界杯为唯一赛事，数据链路和 UI 存在大量硬编码耦合。世界杯赛后插件即失效，需泛化为通用足球直播工具。

### 1.2 目标

| # | 目标 | 验收标准 |
|---|---|---|
| G1 | 多赛事支持 | 内置 ≥8 个赛事目录（五大联赛 + 欧冠 + 中超 + 世界杯），可按赛事过滤所有 Tab |
| G2 | 全部赛事视图 | 「赛程/直播」支持"全部赛事"聚合视图（某天所有足球比赛一屏可见） |
| G3 | 零配置保持 | 不新增任何用户必须填写的 token/key |
| G4 | 积分榜泛化 | 联赛（单表 20 队）与国家队赛事（分组）两种积分榜布局自动适配 |
| G5 | 关注机制 | 用户可关注赛事，StatusBar 与轮询只针对关注赛事，控制请求量 |
| G6 | 平滑升级 | 已安装用户升级后配置不丢（决定点 D1，见 §8） |

### 1.3 非目标

- 不做视频/音频直播，仅比分 + 文字类信息（与现状一致）
- 不做用户自建数据源/自定义 API（保持内置目录 + 开关，不做自由文本输入）
- 不引入新的重量级依赖

## 3. 总体架构

核心思路：**引入「赛事（League）」为一等公民**，数据层所有接口按赛事参数化，调度层只轮询用户关注赛事，UI 层加全局赛事选择条。

```
[百度体育 tiyu.baidu.com, 移动 UA, 无鉴权, SSR s-data]
   │ /al/match/list          → 88 个足球赛事目录
   │ / (首页)                → 全足球 3 天聚合 (含比分/状态/base64 matchId)
   │ /al/match?tab=排名      → 积分榜 (杯赛分组 / 联赛单表 双形态)
   │ /al/live/detail         → 单场详情 + 文字直播
   │ /al/api/realtime        → 新闻 (关键词=所选赛事)
        │ OkHttp + Gson (JsonReader lenient 解析 s-data)
        ▼
BaiduMatchListClient ──► LeagueRegistry (@Service, 目录 30min TTL + DEFAULT fallback)
        │                       │  followed / selected (持久化 FifaSettingsState) + listeners
        ▼                       ▼
┌────────────── FootballDataManager (@Service, 替代已删除的 TournamentManager) ──────────┐
│  scheduleWithFixedDelay 60s: fetchAllFootball() 单请求 →                               │
│    liveMatches (直播中) / todayMatches (今日) → MatchCache("all-football")             │
└──────────┬────────────────────────────────────────────────────────────────────────────┘
           ▼
[LeagueFilterBar 全局赛事选择条: 全部赛事 | 关注赛事 | 目录其余]  ← 5 Tab 共享过滤
           ▼
5 Tab: 赛程 / 直播 / 球队榜(积分榜 flatten 跨组) / FIFA排名 / 新闻  + StatusBar widget
（原独立「排名」Tab 已移除 — 球队榜与排名同源 (BaiduRankingsClient)，保留 flatten 视图即可）
（所有面板的网络拉取均包 executeOnPooledThread，Swing 更新回 EDT）
```

### 3.1 关键设计决策

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 插件 id 是否更换 | ✅ **已确认（2026-10-26）：保留 id `com.fifa.plugin.worldcup2026`，只改 display name，老用户持续升级** | 换 id = Marketplace 视为新插件，老用户断升级；name/description/ToolWindow 展示名随便改 |
| D2 | 全部赛事赛程主源 | ✅ **已定（2026-10-26 PoC）：百度首页 `/` 全足球聚合**（固定昨天/今天/明天 3 天窗口），赛事目录走 `/al/match/list` | 浏览器实测百度无日期参数的隐藏 XHR，前端过滤在客户端完成；TheSportsDB `eventsday?s=Soccer` 无需再验证。TheSportsDB 全线降级为不再依赖 |
| D3 | 实时比分主源 | ✅ **已定：百度首页聚合过滤直播中（`matchStatus`），延续 IN_PLAY 语义**；TheSportsDB v2 livescore 不再考虑 | 聚合数据自带比分与状态，60s 轮询单请求覆盖全部赛事 |
| D4 | 联赛积分榜 | ✅ **已定：全部走百度 `/al/match?tab=排名`，双形态自适应解析**（杯赛分组 / 联赛单表，见 §3.2） | 浏览器实测两种形态共享 `record[5]` 队伍行结构，一套解析器即可；TheSportsDB lookuptable 弃用 |
| D5 | 球队榜 Tab 去留 | ✅ **已定：保留，按所选赛事 flatten 全部组/表做跨组排序**（`fetchTeamRankings(league)`） | 联赛单表 flatten 后即原表顺序，信息不重复，无需按赛事类型隐藏 |

### 3.2 已验证数据源结构（2026-10-26 浏览器 + curl 实测，PoC 结论）

百度体育为 san 框架 SSR：**推荐走 async 纯 JSON 形态**（URL 加 `async_source=h5&from=baidu_shoubai_na&request__node__params=1`），响应为 `{"common":{...},"tplData":{"data":{...同构数据...}}}`；s-data HTML 形态仅作兜底。**实测企业零信任代理（奇安信 QAX）会劫持 SSR 页面型请求**（返回壳响应，IDE 环境复现 100% 失败），async JSON 形态稳定可用——这是 runIde 实测踩坑后确定的方案，解析器已做成双模式（`parseResponseRoot`：`{` 开头按 JSON 解析，否则提取 s-data）。

| 端点 | 数据路径 (async 形态) | 关键字段 |
|---|---|---|
| `GET /al/match/list?async_source=h5...` | `tplData.data.tabList[title=足球].children[0].list[]` | **88 个足球赛事**：`name`(=百度 match 参数, 如"英超")、`logo`、`text`("今日1场")、`DayCount`/`DayIngCount`、`Order`、`Category:"football"` |
| `GET /?async_source=h5...` | `tplData.data.liveList[0](热门).data[]` | 按日分组 `{time:"2026-10-25", weekday:"昨天", list:[rows]}`；行内 `matchType:"football"`、`game`(赛事名)、`matchName`(轮次)、`matchStatus`(0/1/2)、`key`(**base64 matchId**)、`leftLogo/rightLogo{name,logo,score}`、`startTime`；**固定 昨天/今天/明天 3 天窗口**（实测某日 46/22/31 场） |
| `GET /matchlist` | s-data `matchList[]` | 256 张赛事卡（未采用） |
| `GET /al/api/match/schedules?match=X&date=D` | 纯 JSON | 按赛事查询；`game` 字段可能为空（世界杯硬过滤已移除） |
| `GET /al/match?match=X&tab=排名&async_source=h5...` | `tplData.data.tabsList...` | **双形态**：杯赛分组 (`type=groupStage`) / 联赛单表 (`type="1"`)，队伍行 `record[5]` 一致 |
| `GET /al/live/detail?matchId=` | 纯 JSON | 不变 |

**落地结论**：所有请求带 `async_source=h5` 走 JSON API；客户端每类响应同时兼容 async JSON 与 s-data 两种外层布局。TheSportsDB 全部端点不在主链路。

### 4.2 数据层改造（5 个客户端）

**TheSportsDB — `FootballDataClient`**

1. 删除 `leagueId/season` 可变字段及 setter（`FootballDataClient.java:58-79`），所有方法签名加 `League` 参数 —— 当前"单例服务 + 可变配置"在多赛事并发下不安全。
2. `normalizeAndFilter()`（`:505-525`）：移除 `world cup` 过滤；反序列化后的 `strLeague` 保留在 `Match` 上（新增 transient 字段 `leagueName`），过滤责任上移到调用方（按所选赛事/全部）。
3. 新增 `fetchAllSoccerByDate(LocalDate)`：`eventsday.php?d=...&s=Soccer`，一次拿全量足球赛事 —— G2 的数据基础，也是 D2 决策的落点。
4. `fetchScheduleByDate` 现有 rounds 实现（`:203-232`）改名为 `fetchCupScheduleByDate(League, date)`，仅 `category=NATIONAL/CUP` 且百度无数据时走。
5. `fetchStandings(League)`：联赛 → `lookuptable.php?l={id}&s={season}` 直接用 `StandingResponse.standings` 单表；杯赛 → 现有 `computeGroupStandings()` 本地计算路径（rounds 假设随之参数化，不写死 1-3/4-8）。
6. 新闻 `fetchBaiduNews(String keyword)`，关键词由 UI 按所选赛事传入（默认 `足球`）。
7. 共享 OkHttpClient：5 个客户端各自 new 的现状顺手收敛（抽取一个包内 `HttpClients` 工具），降低连接开销（呼应 CLAUDE.md 已知缺口）。

**百度 — `BaiduSportsClient` / `BaiduRankingsClient` / `BaiduFifaRankingsClient`**

1. `MATCH_NAME` 常量删除，`fetchSchedule(League)` / `fetchSchedule(String baiduKey)`；`parseBaiduMatch()` 中 `:169` 的世界杯过滤改为"不过滤"（由调用方决定），`matchName`（如"英超第28轮"）存入 `Match.leagueName` 供 UI 展示分组。
2. `BaiduRankingsClient.fetch(String baiduKey)`；解析层兼容两种形态：
   - `groupStage`（分组，现有逻辑泛化为 N 组，不限定 A-L）→ `Map<组名, List<BaiduRankedTeam>>`
   - 联赛单表（无 groupStage，直接一个大表）→ 放入固定 key `"积分榜"`，UI 据此选布局
   - **PoC 重点**：百度对 `match=英超&tab=排名` 的返回结构是否同样是 `tabsList[].tabList[].data[]` 嵌套，见 §5。
3. `BaiduLiveMatchClient`：按 `baiduMatchId` 取详情，与赛事无关，不改（比赛详情对任何百度赛事 key 都可用）。

**`util/TeamNames`**

- 48 队世界杯映射迁到 `resources/teams-zh.json`（队名→中文），并随 PoC 补充五大联赛常见球队（每队 1 条，约 100-150 条）。
- 查不到 → fallback 英文原名（现状已是 LinkedHash + 大小写不敏感 fallback，机制不变）。百度源本身中文，不受影响。

### 4.3 调度层改造

`TournamentManager` 更名 `FootballDataManager`（保留类名也可，建议一并改，注册点在 `plugin.xml:70-71`）：

```java
// 轮询目标从"单一赛事三元组"变为"关注赛事集合"
volatile Map<String, List<Match>> liveByLeague;     // leagueId -> IN_PLAY
volatile List<Match> todayAll;                       // 全部赛事今日赛程 (eventsday 聚合)
```

### 4.4 UI 改造

1. **新增 `ui/component/LeagueFilterBar`**：ToolWindow 标题行下方的横向选择条 —— 下拉/搜索弹窗（`全部赛事 | ★已关注 | 按类别分组`），选中后写入一个应用级 `LeagueSelectionModel`（简单 POJO + ChangeListener），6 个 Tab 都监听它刷新。这是唯一的新 UI 组件，各 Panel 只加"读 selection → 传参调客户端"的薄层。
2. **赛程 Tab**：日期切换保留；数据源切换为"全部赛事聚合 + 客户端按所选赛事过滤"，`matchName`（赛事名）作为行内副标题展示（如 `英超第28轮`）。
3. **直播 Tab**：按赛事分组渲染（GroupHeader 行），全局选择条过滤生效；60s 百度轮询参数化。
4. **排名 Tab（泛化核心）**：
   - `hasGroupStage=true` → 现有分组 UI（12 组泛化为 N 组 tab/列表）
   - `hasGroupStage=false` → 单表布局（列：排名/球队/赛/胜平负/进失/净胜/积分），数据来自 lookuptable
   - 布局选择由 `LeagueRegistry` 驱动，两个渲染器实现同一接口 `StandingsView`
5. **球队榜 Tab**：仅 `category=NATIONAL/CUP && hasGroupStage` 时有内容，否则显示空态提示（D5）。
6. **StatusBar widget**：显示优先级 = 关注球队命中 > 关注赛事 > 任意进行中；多场进行中时每 10s 轮换一条（`⚽ ARG 2:1 FRA (67')` 格式不变）。
7. 品牌与文案（D1 已确认：**id 不动，只改展示名**，老用户持续升级）：`plugin.xml` 的 `<name>` 改为「足球直播 Football Live」、`<description>` 改为全赛事定位，`<id>` 保持 `com.fifa.plugin.worldcup2026` 不变；标题 `⚽ FIFA World Cup 2026` → `⚽ 足球直播`；ToolWindow 展示名与 Settings displayName 同步。

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
